# ADR-002: Adopt Base UI as the Component Foundation

## Sprint

Sprint 2 — Design System Foundation

## Status

Accepted

## Date

2026-08-04

## Context

The portfolio requires a modern, accessible, and maintainable UI foundation without spending significant development effort on implementing low-level interface primitives.

Rather than building every component from scratch, the project should leverage a proven component foundation while maintaining complete control over the application's visual identity.

## Decision

The project adopts **Base UI (Nova preset)** as the foundation for interactive UI components.

Generated components will serve as low-level primitives and will not define the portfolio's visual identity.

Custom reusable components will be composed on top of these primitives whenever necessary.

## Implementation

Generated components are located in:

```text
src/components/ui/
```

These components:

- are generated by Base UI.
- should remain as close to the generated source as possible.
- should only be modified when absolutely necessary.

Reusable application components are created separately and consume these primitives.

## Consequences

### Positive

- Faster development.
- Accessible components by default.
- Consistent interaction patterns.
- Easier long-term maintenance.
- Reduced implementation effort.

### Negative

- Introduces an external dependency.
- Requires reviewing generated components when upgrading Base UI.
